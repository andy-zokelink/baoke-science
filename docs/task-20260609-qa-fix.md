## 第二阶段：新增在线测试功能

### 功能描述
在「错题诊疗」页面中，新增一个「生成在线测试」按钮，点击后基于错题生成在线答题界面。

### 技术方案

在 `docs/index.html` 中新增一个「在线测试」功能模块，基于错题/薄弱知识点生成交互式答题界面。

具体设计：

1. **入口**：在Tab 2（错题诊疗）顶部新增「生成在线测试」按钮
2. **选择题型**：默认从错题（183道）中抽取
3. **生成策略**：
   - 按错误频率排序，优先出高频错题
   - 支持三种模式：易错题专练 / 知识点专练 / 模拟抽测
   - 默认模式：易错题专练（自动选错题中错误频率最高的知识点，每个知识点2-3题）
4. **答题界面**：
   - 命题形式与现实不同：直接用题目卡片，不需要模拟试卷排版
   - 一题一题显示，答完显示正确/错误和解析
   - 底部显示总进度（1/10、2/10...）
5. **数据来源**：全部从 `BAOKE_DATA.questions` + `.answers` 实时计算，不写后端
6. **扩展性**：后续可增加「组卷打印」功能（从题库抽题组成试卷，打印出来）

### 详细交互设计

**进入测试流程**：
1. 用户点击「生成在线测试」按钮
2. 弹出模式选择弹窗（三种模式）：
   - **易错题专练**：从高频错题中抽10题，优先覆盖薄弱知识点
   - **知识点专练**：按选择的知识点，从该知识点错题中抽题
   - **模拟测试**：从全部题库随机抽15题（含已掌握的）
3. 用户选择后开始答题

**答题过程**：
- 每屏只显示1道题
- 题目在上方，选项/填空区域在下方
- 答完一题后显示对错+解析+策略
- 「下一题」按钮继续
- 顶部固定的进度条

**答题结束**：
- 显示成绩总览：答对N/N题，正确率%
- 显示错题回顾（本次答错的题目列表）
- 「重新测试」按钮 / 「返回」按钮

## 重要实现要求

1. **全量自测**：每个功能点都要在浏览器实际打开测试，不能只靠代码审查
2. **发现问题必须修复**：不只是报告问题，要实际修复代码
3. **数据关联验证**：检查 data.js 导出数据时字段名是否正确，concept_id 是否都有值
4. **移动端适配**：在线测试界面必须支持手机浏览
5. **纯前端实现**：不依赖后端，所有数据来自 data.js
6. **保留现有样式**：维持原有蓝色+白色清爽风格，不要重新设计全局样式
7. **修改完毕后**：
   - git add -A
   - git commit -m "修复：全功能检查+错题关联修复+新增在线测试功能"
   - git push

## 执行流程

1. **Step 1**：先查看 data.js 的数据结构，检查字段完整性
2. **Step 2**：打开 docs/index.html 在浏览器中逐项测试每个功能
3. **Step 3**：发现数据关联问题时，检查数据生成脚本和数据库
4. **Step 4**：修复发现的数据关联/JS逻辑问题
5. **Step 5**：新增在线测试功能（易错题专练模式）
6. **Step 6**：再次全量测试验证修复和新功能都正常
7. **Step 7**：git commit + push
